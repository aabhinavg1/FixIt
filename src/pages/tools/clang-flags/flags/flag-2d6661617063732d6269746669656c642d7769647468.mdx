## What this flag actually does

Follow the AAPCS standard requirement stating that volatile bit-field width is dictated by the field container type. (ARM only).



It can be negated with -fno-aapcs-bitfield-width.

## When to use it

- Final link steps
- When forwarding flags to the linker
- Build systems that need linker-specific control

## When not to use it

- Pure compilation steps
- When the linker should not see the option

## Usage example

```bash
clang++ -faapcs-bitfield-width main.o -o app
```

- **Argument form**: Flag (no argument)

- **Stage**: cc1 (frontend), category `Linker`
- **Negated by**: `-fno-aapcs-bitfield-width`
