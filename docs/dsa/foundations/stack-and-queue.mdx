# Stack and Queue

Stacks and queues both store items, but they remove items in different ways.

## In one line

- A **stack** is last in, first out.
- A **queue** is first in, first out.

## Stack example

Think of a pile of books.

The last book you place on top is the first one you take off.

### Real-life use case

Undo in a text editor behaves like a stack.

### Study use case

Use a stack when you need to remember recent steps or move backward through a process.

## Queue example

Think of a line at a ticket counter.

The first person in line is served first.

### Real-life use case

A cafeteria line is a queue.

### Study use case

Use a queue when tasks should be handled in arrival order.

## Why it matters

The order rule changes the behavior.

When the order rule matches the problem, the structure feels natural and the algorithm becomes simpler.

## What beginners should remember

- Stack = recent item first.
- Queue = first item first.
- Choose the structure that matches the order you want to preserve.

## Common mistake

Beginners often mix them up because both are just containers.

The difference is not storage, but removal order.

## Try this

Pick one real action and decide whether it is more like a stack or a queue:

- browser history,
- printer jobs,
- undo/redo,
- customer support tickets.
