# Algorithm

You want to find the fastest route to college, make tea without forgetting a step, or search a contact in your phone.

In each case, you are following a clear sequence of actions to reach a result.
That sequence is an algorithm.

:::note
If you remember one line, remember this: an algorithm is a finite, ordered set of clear steps that turns input into output.
:::

## Introduction

Think about a simple task like making a sandwich.

You do not start by doing random actions.
You first decide the order:

1. take bread,
2. add filling,
3. close the sandwich,
4. cut it,
5. serve it.

That ordered plan is an algorithm.

In computing, the same idea applies.
If a program needs to search, sort, compare, count, or decide, it needs an algorithm.

## Why Learn This?

Algorithms matter because they turn vague problem solving into repeatable steps.

Without an algorithm, a solution is often:

- hard to explain,
- hard to test,
- hard to debug,
- and hard to improve.

With an algorithm, you can reason about correctness and performance before you write code.

:::important
An algorithm is not the same as code. Code is one way to express an algorithm, but the algorithm itself is the method.
:::

## Real-Life Example

Suppose you want to find a book in your room.

You could:

- scan every shelf one by one,
- search only the shelf where you usually keep books,
- or keep the books labeled by category so you can jump to the right place.

Each approach is a different algorithm.

The goal is the same, but the steps are different.
Some are faster, some are simpler, and some use more memory or organization.

## Intuition

The easiest way to understand an algorithm is to think of it as a recipe.

- The ingredients are the input.
- The recipe steps are the algorithm.
- The finished dish is the output.

A recipe works only if the steps are clear enough to follow.
If the steps are vague, different people may produce different results.

That is why good algorithms are precise.

## Definition

In computer science, an algorithm is a finite sequence of unambiguous steps that solves a problem or produces a result.

### Mathematical Definition

An algorithm is a finite sequence of well-defined instructions that transforms input into output and terminates after a finite number of steps.

Good algorithms usually have these properties:

- **Finiteness**: they must stop after a limited number of steps.
- **Definiteness**: each step must be clear.
- **Input**: they may accept zero or more inputs.
- **Output**: they produce at least one result.
- **Effectiveness**: each step must be simple enough to execute.

## History

Algorithms are not a new idea.
Euclid used step-based methods for mathematics more than 2,000 years ago.
The word algorithm comes from the name of Al-Khwarizmi, whose work influenced how ordered procedures were described in later mathematics.
Modern computer science turned that old idea into the core of program design and analysis.

## Step-by-Step Explanation

Suppose you want an algorithm to find the largest number in a list.

Step by step:

1. Start with the first number as the current largest.
2. Compare the next number with the current largest.
3. If the next number is larger, replace the current largest.
4. Repeat until you reach the end.
5. Return the largest number.

This is a good beginner algorithm because it is simple, clear, and easy to trace.

If you want a refresher on the values the algorithm works with, go back to [What Is Data?](./data).
If you want to see another common beginner structure after this page, move to [Arrays](./arrays).

The same pattern appears in many problems:

- scan data once,
- keep track of the best value seen so far,
- update it when needed,
- stop at the end.

## Code

Here is the same algorithm in three languages.

<Tabs>
<TabItem value="cpp" label="C++">

```cpp
#include <iostream>
#include <vector>
#include <stdexcept>
using namespace std;

int findMax(const vector<int>& nums) {
    if (nums.empty()) {
        throw invalid_argument("List must not be empty");
    }

    int best = nums[0];
    for (size_t i = 1; i < nums.size(); ++i) {
        if (nums[i] > best) {
            best = nums[i];
        }
    }
    return best;
}

int main() {
    vector<int> nums = {4, 7, 2, 9, 5};
    cout << findMax(nums) << '\n';
    return 0;
}
```

```python
def find_max(nums):
    if not nums:
        raise ValueError("List must not be empty")

    best = nums[0]
    for value in nums[1:]:
        if value > best:
            best = value
    return best


nums = [4, 7, 2, 9, 5]
print(find_max(nums))
```

<TabItem value="java" label="Java">

```java
public class Main {
    static int findMax(int[] nums) {
        if (nums == null || nums.length == 0) {
            throw new IllegalArgumentException("List must not be empty");
        }

        int best = nums[0];
        for (int i = 1; i < nums.length; i++) {
            if (nums[i] > best) {
                best = nums[i];
            }
        }
        return best;
    }

    public static void main(String[] args) {
        int[] nums = {4, 7, 2, 9, 5};
        System.out.println(findMax(nums));
    }
}
```

### What the code shows

- The algorithm is the same in every language.
- The data changes, but the steps stay the same.
- The loop is the core of the algorithm.
- Each value is compared once.

### Intuition for complexity

You cannot know the maximum without looking at the data.
That is why the time grows linearly with the list size.

For many algorithms, the key question is:

- How many times do I scan the input?
- Do I sort before searching?
- Do I store extra information to save time later?

:::caution
The same problem can have many algorithms. A correct algorithm is not automatically a fast one.
:::

## Comparison Tables

### Algorithm vs Program

| Aspect | Algorithm | Program |
| --- | --- | --- |
| Meaning | A step-by-step method to solve a problem | Code written in a programming language |
| Language dependence | Language-independent | Language-specific |
| Form | Plain steps, pseudocode, flowchart, or code idea | Actual source code |
| Goal | Describe the solution | Run the solution |
| Example | "Compare each item and keep the largest" | A C++ or Python function that does it |

### Algorithm vs Data Structure

| Aspect | Algorithm | Data Structure |
| --- | --- | --- |
| Main focus | Steps and operations | Storage and organization |
| Question it answers | "What do I do?" | "Where and how do I keep it?" |
| Example | Linear search, merge sort, BFS | Array, stack, queue, tree, graph |
| Trade-off | Time and logic | Access, insert, delete, and memory cost |

### Algorithm vs Recipe

| Aspect | Algorithm | Recipe |
| --- | --- | --- |
| Input | Problem data | Ingredients |
| Steps | Clear computational actions | Cooking actions |
| Output | Result or answer | Finished dish |
| Important rule | Steps must be unambiguous | Steps must be followable |

## Real Applications

Algorithms are everywhere.

- **Google Search** uses ranking and retrieval algorithms to decide what results to show first.
- **Linux** uses scheduling, memory-management, and file-system algorithms inside the kernel.
- **Databases** use indexing, query-planning, and join algorithms to answer requests efficiently.
- **Browsers** use rendering, parsing, layout, and caching algorithms.
- **Compilers** use parsing, optimization, register allocation, and code generation algorithms.
- **AI** uses training, inference, search, and optimization algorithms.
- **Robotics** uses path planning, control, and sensor-fusion algorithms.
- **Cloud Computing** uses load balancing, replication, and scheduling algorithms.
- **Operating Systems** use process scheduling, paging, and disk allocation algorithms.
- **Games** use pathfinding, collision detection, AI decision trees, and physics algorithms.

## Advantages

- Algorithms make problem solving repeatable.
- They help you separate logic from implementation.
- They make debugging easier.
- They let you compare efficiency before coding.
- They can be written before choosing a programming language.

## Limitations

- A good algorithm still needs good input.
- Some problems have no perfect exact solution.
- A short algorithm is not always the fastest.
- A correct algorithm can still use too much memory.
- Real-world constraints can change the best choice.

## Common Mistakes

1. Writing steps that are too vague.
2. Forgetting to define when the algorithm stops.
3. Skipping edge cases like empty input.
4. Confusing the algorithm with the programming language.
5. Choosing code before understanding the problem.
6. Ignoring time and space cost.
7. Testing only one example instead of several.
8. Assuming the first working idea is the best one.
9. Mixing data storage decisions with step logic.
10. Not explaining why each step exists.

## Memory Tricks

- **Algorithm = ordered actions**
- **Recipe for a computer**
- **Input in, output out**
- **Clear steps, clear result**
- **If a friend can follow it, it is probably an algorithm**

## FAQs

1. **What is an algorithm?** An algorithm is a clear, ordered set of steps for solving a problem.
2. **Is an algorithm always code?** No. It can be described in words, pseudocode, flowcharts, or code.
3. **Does every program contain an algorithm?** Yes. Any useful program uses one or more algorithms.
4. **Can two programs use the same algorithm?** Yes. The implementation can change while the idea stays the same.
5. **Can an algorithm be wrong?** Yes. It may solve the wrong problem or fail on some inputs.
6. **Can an algorithm be slow but correct?** Yes. Correctness and efficiency are different questions.
7. **Why should algorithms be finite?** Because a solution that never stops is not useful.
8. **What does unambiguous mean?** Each step should have only one clear meaning.
9. **What is a step-by-step procedure?** It is a sequence where each action follows the previous one.
10. **Why do algorithms matter in DSA?** Because DSA combines data storage with problem-solving steps.
11. **What is the input of an algorithm?** The input is the data the algorithm works on.
12. **What is the output of an algorithm?** The output is the result the algorithm produces.
13. **Can an algorithm have no input?** Yes. Some algorithms generate values or follow a fixed process.
14. **Can an algorithm have more than one output?** Yes. Some problems return multiple values.
15. **What is pseudocode?** Pseudocode is a human-friendly way to describe algorithm steps.
16. **What is the simplest algorithm example?** Finding the largest value in a list is a common beginner example.
17. **Why do we dry run algorithms?** To check logic before writing or running code.
18. **What makes an algorithm good?** Clarity, correctness, and reasonable efficiency.
19. **Can there be many algorithms for one problem?** Yes. Different algorithms can solve the same task in different ways.
20. **Is the fastest algorithm always best?** No. Simpler algorithms may be better for small inputs.
21. **What is brute force?** Brute force checks many or all possibilities directly.
22. **What is an optimized algorithm?** It is an algorithm designed to do less work or use less memory.
23. **Do algorithms use data structures?** Often yes, because the storage shape can speed up the steps.
24. **What should I learn after algorithms?** Arrays are a natural next step because they are easy to use in examples.
25. **Why do interviewers ask about algorithms?** They want to see how you think through a problem, not just whether you know syntax.

## Summary

- An algorithm is a clear sequence of steps.
- It solves a problem by turning input into output.
- Good algorithms are finite, precise, and testable.

- Time and space complexity help you compare algorithms fairly.
- In DSA, algorithms work together with data structures.
