# Connected Data

Not all data lives in a straight row.

Some data points to other data.

## In one line

Connected data structures are used when relationships matter more than a simple list.

## Linked list

A linked list is like train cars connected one after another.

Each node knows where the next node is.

### When it fits

Use it when the order matters, but the connection is more important than direct indexing.

## Tree

A tree is a branching structure.

A folder system on your computer is a simple example.

### When it fits

Use it when you have hierarchy, parent-child relationships, or repeated branching.

## Graph

A graph is a network of connections.

Road maps, social networks, and dependency diagrams are graphs.

### When it fits

Use it when one thing can connect to many things and the path itself matters.

## Study use case

A course roadmap can be modeled as connected data:

- one topic leads to the next,
- one chapter branches into subtopics,
- and some lessons connect across multiple paths.

## Why it matters

These structures help when the problem is about relationships rather than just rows.

That is why they appear in road planning, folder systems, social apps, and dependency tracking.

## What beginners should remember

- Linked list: one connection after another.
- Tree: branching hierarchy.
- Graph: network of relationships.

## Common mistake

Do not force everything into a list when the real problem is about connections.

## Try this

Draw a simple graph of things you know:

- subjects,
- prerequisites,
- tools,
- or friends.

Then ask whether the shape is really a list, a tree, or a graph.
